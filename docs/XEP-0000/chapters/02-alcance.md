# Capítulo II — Alcance

## Artículo 4. Cambios que requieren un XEP

Deberá presentarse un XEP cuando una propuesta pretenda:

1. modificar principios constitucionales;
2. alterar la gobernanza institucional;
3. crear o modificar un estándar editorial;
4. cambiar la arquitectura conceptual o técnica;
5. establecer políticas generales de producto;
6. crear, sustituir o retirar un volumen fundacional;
7. modificar procesos formales de revisión o aprobación;
8. introducir decisiones estratégicas con efectos de largo plazo;
9. establecer incompatibilidades con versiones anteriores;
10. modificar el propio proceso XEP.

## Artículo 5. Cambios que no requieren un XEP

No será necesario presentar un XEP para:

1. corregir ortografía, puntuación o sintaxis sin alterar el significado;
2. reparar enlaces o referencias rotas;
3. ajustar formato o presentación sin efecto conceptual;
4. actualizar fechas, nombres o metadatos puramente administrativos;
5. corregir errores técnicos evidentes cuya solución no implique una decisión
   de diseño;
6. realizar mantenimiento rutinario previamente autorizado.

Estas correcciones deberán conservar, en todos los casos, trazabilidad mediante
Git y una descripción clara del cambio.

## Artículo 6. Casos dudosos

Cuando no resulte claro si una modificación requiere un XEP, deberá preferirse
la documentación formal si el cambio puede afectar principios, derechos,
responsabilidades, interoperabilidad, compatibilidad, gobernanza o confianza
institucional.
